# Изменения

## 2. Ускорение запуска скриншота

Ветка: `claude/inspiring-bohr-qceeql` — новая работа поверх `main` после слияния PR #1.

### Что тормозило
Замеры на реальном Electron 36: Linux + Xvfb, экран 5120×2880 (столько же пикселей, сколько у 5K Retina), на экране текст, интерфейс и участок «фото».
- `toDataURL()` — кодирование снимка в PNG + base64 в main: **~800 мс**.
- Передача строки ~8 МБ в окно и декодирование PNG: **~400–550 мс**.
- Окно выделения и окно редактора создавались заново на каждый снимок; в dev-режиме они ещё и грузили модули с Vite.
- При выделении обрезка ещё раз кодировалась в PNG в окне и декодировалась в редакторе.
- При «копировать сразу» PNG декодировался обратно в main: ~200–400 мс.

### Что сделано
1. **Без PNG на пути захвата.** Снимок остаётся в main как `NativeImage`, в окна уходят сырые пиксели BGRA (`toBitmap`, ~36 мс для 5K). Выделение обрезается в main (`cropCapture` в `src/main/capture.ts`, ~3 мс). В буфер копируется прямо `NativeImage`.
2. **Пиксели не пересекают contextBridge.** Копирование 59 МБ через мост в страницу стоило 0,35–1,6 с. Поэтому preload сам рисует картинку в `<canvas>` страницы (`drawCapture` в `src/preload/index.ts`), а через мост идут только canvas и размеры.
3. **Окна наготове.** Скрытые, уже загруженные окно выделения и редактор создаются при запуске и через 1 с после каждого снимка (`prepareCaptureWindow` / `takeCaptureWindow` в `src/main/windows.ts`). Если запасного окна нет, создаётся новое, как раньше. Ожидание загрузки всегда завершается: при ошибке загрузки, падении renderer'а или закрытии окна.
4. **Окно выделения появляется сразу после снимка** (`showInactive`). Затемнение и перекрестие в нём уже нарисованы, а «замороженная» картинка подкладывается под них через доли секунды — это тот же кадр, так что подмены не видно. Фокус окно берёт после отрисовки (`show()` + `focus()`), чтобы активное приложение не «гасло» раньше времени. Благодаря `acceptFirstMouse` выделять можно сразу, даже до отрисовки картинки: обрезка всё равно делается в main по полному снимку.
5. **Редактор показывается, когда картинка уже на холсте** (подтверждение `capture:drawn`, запасной таймаут 1 с). Он центрируется на мониторе, с которого сделан снимок.
6. **Протокол окон.** main регистрирует снимок за окном и шлёт сигнал без данных `capture:available`. Страница забирает снимок (`capture:request`) при монтировании и по сигналу. Так сигнал не теряется, а перезагрузка окна сохраняет картинку.

### Попутные исправления
- **Выделение при отпускании мыши считается по координатам самого события.** Раньше брался последний отрисованный стейт React, и при быстром движении или занятом потоке выделение получалось меньше, вплоть до отмены. Нашлось на замерах.
- **Повторное нажатие горячей клавиши** больше не оставляет лишнее окно выделения, которое нельзя закрыть. Новый захват отменяет результат старого (`captureSeq`), а Esc и выделение закрывают именно своё окно. Флага, который мог «залипнуть» при зависшем снимке, нет.
- Открытое окно выделения при новом захвате (в том числе полноэкранном) сначала прячется, чтобы не попасть в кадр.
- `setVisibleOnAllWorkspaces(..., { skipTransformProcessType: true })`. Приложение и так без иконки в Dock, а переключение типа процесса при каждом вызове на мгновение скрывает все окна, включая открытый редактор.
- Редактор перечитывает настройки при каждом снимке (окно могло долго висеть скрытым) и не пишет на диск те же значения повторно.
- В dev-режиме каждый захват пишет тайминги в терминал: `[capture] region: screen grabbed after …ms`, `overlay shown`, `overlay image drawn`, `editor shown`. Это описано в README.
- `tsconfig.node.json` больше не включает preload. Preload работает в окне с DOM и проверяется веб-конфигом через `src/preload/index.d.ts`.

### Результаты
Медианы 6–7 прогонов, экран 5120×2880, одинаковый сценарный стенд для старого и нового кода:

| Сценарий | Было (prod / dev) | Стало (prod / dev) |
|---|---|---|
| горячая клавиша → окно выделения на экране | 1397 / 1432 мс | **176 / 183 мс** |
| … «замороженная» картинка под затемнением | 1397 / 1432 мс | 634 / 647 мс |
| выделение → редактор | 379 / 362 мс | **181 / 117 мс** |
| полный экран → редактор | 1581 / 1536 мс | **661 / 641 мс** |

В старом коде окно выделения до загрузки картинки было полностью прозрачным, поэтому для него «видно» = «картинка нарисована». Из ~176 мс нового времени почти всё уходит на сам снимок (`desktopCapturer.getSources`).

### Проверка
- `npm run typecheck` и `electron-vite build` проходят чисто.
- Сценарный тест на реальном Electron — 11/11 и в production-сборке, и в dev-режиме (Vite + React StrictMode):
  - пиксели редактора совпадают с экраном после выделения и после полного экрана (проверены обрезка и порядок байтов);
  - выделение до того, как картинка нарисована;
  - Esc;
  - двойное нажатие горячей клавиши;
  - перезагрузка редактора;
  - отсутствие лишних записей настроек.
- На macOS не запускал. Проверить на Mac:
  - скорость (тайминги в терминале);
  - фокус и Esc в окне выделения;
  - Spaces и полноэкранные приложения;
  - два монитора с разным масштабом.

### Что осталось и чем платим
- Сам снимок (`desktopCapturer.getSources`) здесь занимает ~200 мс, на Mac может быть дольше. Его время видно в строке `screen grabbed`. Если основная задержка окажется там, следующий шаг — отдельная оптимизация захвата под macOS.
- Два скрытых запасных окна держат в памяти два процесса renderer'а (обычно десятки МБ каждый).
- Пока открыт редактор, main хранит его снимок (для 5K — ~59 МБ), чтобы окно пережило перезагрузку.

## 1. Исправления после ревью кода (PR #1, слит)

Ветка: `claude/inspiring-bohr-qceeql`

### Ошибки

#### 1. Редактор перезаписывал настройки
Раньше редактор держал копию **всех** настроек и сохранял её целиком при каждой смене цвета, толщины или рамки. Если во время открытого редактора что-то поменять в окне Settings, эти изменения терялись. Кроме того, каждое сохранение заново регистрировало горячие клавиши и автозапуск.

- `src/shared/types.ts` — новый IPC-канал `settings:setEditorPrefs`.
- `src/main/store.ts` — `saveEditorPrefs()` обновляет только `editorPrefs`. `saveSettings()` теперь всегда берёт `editorPrefs` из хранилища, поэтому окно Settings тоже не может затереть настройки редактора.
- `src/main/index.ts`, `src/preload/index.ts` — обработчик и метод `window.api.setEditorPrefs`.
- `src/renderer/editor/Editor.tsx` — сохраняются только настройки редактора, с задержкой 300 мс (ползунок не пишет конфиг на каждом движении) и только после загрузки сохранённых значений.

#### 2. Отмена и повтор в StrictMode
В `undo`/`redo` один `setState` вызывался внутри функции-обновлятора другого, а при отпускании мыши внутри обновлятора вызывался `commit`. В режиме разработки React вызывает такие функции дважды, и в истории появлялись лишние записи.

- `Editor.tsx` — обновляторы стали чистыми. `undo`/`redo` читают стеки напрямую, текущая фигура хранится в `draftRef`. Клик по пометке в режиме выделения без перемещения больше не создаёт пустую запись в истории.

#### 3. Номера шагов
Счётчик `stepRef` не откатывался при отмене или удалении. Теперь новый номер равен максимальному номеру на холсте плюс 1.

#### 4. Нет проверки доступа к записи экрана
`src/main/capture.ts` — `hasScreenAccess()` возвращает `false` только при статусах `denied`/`restricted` (при `not-determined` macOS сама покажет запрос). `src/main/index.ts` — перед снимком без доступа показывается диалог с кнопкой «Open System Settings», которая открывает нужный раздел настроек.

#### 5. Полноэкранный снимок только с основного монитора
Теперь полный экран снимается с монитора под курсором. Функция `capturePrimaryDisplay` удалена.

### Безопасность
- `src/main/windows.ts` — у всех окон `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`. Проверено, что preload собирается в CJS и требует только `electron`, то есть совместим с песочницей. Новая функция `lockDown()` запрещает навигацию и открытие новых окон во всех окнах; http(s)-ссылки открываются в браузере.
- `electron.vite.config.ts` — Content-Security-Policy добавляется в `index.html` только при production-сборке (в dev плагин React вставляет inline-скрипт для Fast Refresh).
- `src/main/uploader.ts`, `Settings.tsx`, `README.md` — при ошибке Supabase 400/401/403 выводится подсказка про публичный бакет и политику `INSERT` для роли `anon`. Требования расписаны подробнее.

### Мелочи
- Удалены неиспользуемые импорты (`shell`, `hasScreenAccess` теперь используются). `npm run typecheck` проходит без ошибок (раньше было 2).
- Типы `Frame`/`Background` перенесены в `src/shared/types.ts`. `frame.ts` их реэкспортирует, приведение `as Frame` больше не нужно.
- `annotations.ts` — размер текстовой пометки считается через `measureText` с учётом многострочного текста, поэтому выделение и перетаскивание работают точно.
- `index.ts` — на Windows и Linux в трее рисуется программная иконка ◉ (раньше иконка была пустой). На macOS всё осталось как было.
- `package.json` + `scripts/kill-stale.mjs` — `pkill`/`sleep` перенесены в кроссплатформенный скрипт `predev`. Команда `npm run dev` теперь работает и на Windows.
- `README.md` — исправлена команда клонирования (`artemleadl/printscreen`), структура проекта и описание полного экрана.

### Проверка
- `npm run typecheck` и `electron-vite build` проходят чисто.
- Production-сборку редактора с включённым CSP я прогнал в Chromium (Playwright) с поддельным `window.api`: отмена, повтор, лишняя отмена, нумерация шагов после отмены, сохранение настроек только через `setEditorPrefs`. Всё прошло.
- В самом Electron на macOS не запускал (в окружении нет macOS). Вручную стоит проверить: снимок области и полного экрана на двух мониторах, диалог при отключённом доступе к записи экрана, загрузку в Supabase.
